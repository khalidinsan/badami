How data flows

The frontend never opens the database file directly. It calls Tauri commands, which the Rust side serves from the open libsql connection:

  1. A store action calls invoke("db_query", …) or invoke("db_execute", …).
  2. Kysely builds the SQL through a custom dialect whose driver is that invoke call, so queries stay type safe on the frontend.
  3. Rust runs it against badami.db, or against the sync replica when cloud sync is on.

Local Dev services are the exception: they are real processes, not rows. The supervisor owns their lifecycle, and the database only records intent and a status snapshot for the UI. Runtime truth comes from the process table and the health checks.

Which database file is opened

On startup the backend picks a connection strategy so the app works offline:

Situation What is opened
Sync on, replica exists The replica, immediately, with no network wait.
Sync on, no replica yet badami.db while the replica is built in the background.
Sync off badami.db as a plain SQLite file.

Local Dev internals

The module is split so each file has one job:

File Responsibility
discovery.rs Reports what binaries, datadirs, ports, and resolver entries exist.
runtime_manifest.rs Reads and writes the manifest that records installed versions and their hashes.
runtime_updater.rs Downloads, verifies, extracts, and installs a version from upstream.
datadir_migration.rs Assesses and performs the APFS clone of a MariaDB datadir.
config_gen.rs Generates nginx, FPM, dnsmasq, valet, and MariaDB configs.
service_specs.rs Turns discovery into runnable service definitions with health checks.
supervisor.rs Starts, stops, restarts, and watches the services; owns the event stream.
sites.rs Park, link, isolate, secure, and open a site.
tls.rs Local CA and per-site certificates.
bootstrap.rs Root-owned LaunchDaemon and resolver installation.
doctor.rs Read-only diagnostics and the fixes they suggest.
mariadb_guard.rs The pre-start checks that stop a second server opening one datadir.

Sync and machine-specific data

Cloud sync replicates the database, but some rows describe this machine only: binary paths, sockets, and Local Dev settings. Those tables are excluded from sync so a second machine does not inherit paths that do not exist on it.
