Database client

Connect to MySQL, PostgreSQL, and SQLite from inside the app, browse what is there, change the schema, and run queries in tabs.

Connections

The sidebar lists your saved connections. Each one holds the engine, host, port, database, username, and how to authenticate.

Engine Notes
MySQL and MariaDB Connects over TCP. Works with a local server or a remote host.
PostgreSQL Connects over TCP, with an optional schema to open first.
SQLite Opens a file on disk. No server, no credentials.

SSL and SSH tunnels

A connection can require TLS, and can be routed through an SSH server when the database is only reachable from inside a network. The SSH side reuses the same credentials and PEM keys as the Servers module, so a host you already added there can be selected instead of retyping it.

Passwords

Database passwords go to the operating system keychain, not into the app database. The connection row records everything except the secret.

Registering the local stack

If you use Local Dev, the MariaDB it manages can be registered as a connection with one click from the Local Dev panel, so the local database appears here without typing host and port by hand.

Browsing objects

Once connected, the object browser lists schemas, tables, views, and columns. Selecting a table shows its structure and lets you page through its rows.

What you can do Where
Inspect columns, types, keys, and defaults The table structure view.
Read rows with paging The table data view.
Filter and sort without writing SQL The column headers and the filter row.
Edit a cell in place Double-click a cell in the data view.
Insert or delete a row The row controls in the data view.

Query editor

Each query opens in its own tab, so you can keep several statements side by side and switch between them. Results appear below the editor, and the last run stays until you run something else.

Action How
Run the statement The run button, or the usual keyboard shortcut for your platform.
New query tab Cmd+T.
Close the tab Cmd+W.
See what you ran before The query history panel.

Schema changes

Tables and columns can be created, altered, and dropped from the interface. The statement the app is about to run is shown before it executes, so a change is never applied silently.

Export and import

Query results and whole tables can be written out, and data can be read back in. The format is chosen when you start the export.

Project scoping

A connection can be attached to a project, which adds a Database tab inside that project so the relevant database is one click away while you work on it.

Destructive statements are not sandboxed

The editor sends what you write. A DROP or a DELETE without a WHERE runs immediately, against whatever connection is selected. Check the connection name before running anything that destroys data.
