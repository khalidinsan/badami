Credential vault

A single master password protects every login, key, and note you keep in Badami, all encrypted before it touches the database.

The master password

The vault is locked behind one master password. Everything inside is encrypted with AES-256-GCM, and the key is derived from the master password with Argon2. Unlocking the vault is what makes the entries readable; until then they are ciphertext.

The vault auto-locks after a configurable idle period. The default is 15 minutes. There is also a password hint setting in case you forget the master password.

One password gates everything

The master password is the only key to the vault. If you set a hint, it is there to jog your memory; the hint itself does not unlock anything.

Credential types

There are nine types, each with its own secret fields:

Type For
Web loginSite logins with a username and password.
App accountDesktop and mobile app accounts.
API keyService tokens and keys.
DatabaseDatabase connections.
EmailMail accounts.
LicenseSoftware license keys.
Secure noteFree text that has to stay secret.
Environment variablesKey and value pairs for a project.
Server accessMachine credentials that can be linked to a server.

Common fields

Every credential also carries these fields, on top of the type-specific secrets:

  • Name.
  • Username.
  • URL.
  • Service name.
  • Environment: Production, Staging, Development, or None.
  • Tags.

TOTP

A credential can hold a shared secret for two-factor codes. Badami generates the current 6-digit code and shows a countdown until it rolls over. SHA1, SHA256, and SHA512 are supported.

Password generator

When you are creating a new secret, the generator builds a strong password for you instead of leaving you to invent one.

Linking

Credentials do not have to stand alone:

  • A credential can be linked to a project.
  • A Server access credential can be linked to a server, and the server form's From Credential Manager authentication option points at it.
Two separate secret stores

The vault master password is separate from your operating system keychain. Server passwords live in the keychain. Vault secrets live in the encrypted vault. Unlocking one does not unlock the other.
