Sync

Optional replication of your database to a Turso instance, so the same work is available on more than one computer. Off unless you turn it on.

How it works

Badami keeps a local database on each machine and an embedded replica of your remote Turso database beside it. Writes go to the local file first and replicate in the background, which is why the app stays fast and keeps working with no network.

Situation What opens
Sync on, replica already exists The replica, immediately. No network wait on startup.
Sync on, no replica yet The local database while the replica is built in the background, so the app is usable during the first sync.
Sync off The local database as a plain SQLite file.

Turning it on

  1. Create a database at turso.tech.
  2. Open Settings → Cross-Device Sync, turn sync on, and paste the database URL.
  3. On the second computer, use the same URL. Its replica is created from the remote copy on first run.

What syncs, and what does not

Documents and records replicate: projects, pages, tasks, labels, credentials, servers, API collections, and database connections.

Some things deliberately stay on the machine that made them:

Not synced Why
Secrets in the operating system keychain Server passwords and PEM passphrases are held by the system keychain and are never part of the database, so they cannot replicate. Add them on each machine.
Your AI provider key Kept local so a shared database does not hand your key to another machine.
Local Dev tables Paths, ports, sockets, and service rows describe one machine. Syncing them would point a second computer at directories that do not exist there.
The vault master password Vault contents replicate, but the key that decrypts them is derived from the master password you enter, which is never stored.

Credentials replicate, so protect the remote database

Vault entries are encrypted before they are stored, and they do replicate. If your Turso database is readable by someone else, they get ciphertext, not your secrets, but they do get your project and task data in the clear. Treat the remote database as you would any copy of your notes.

Sync is not a backup

It keeps two machines in step. It does not keep history, so a deletion on one machine becomes a deletion on the other. For a copy you can go back to, export or copy the local database file yourself.
