REST API tool

Build a request, organize it in a collection, switch environments, and read the response without leaving Badami.

Building a request

The request view has a method selector and a URL field, then tabs for the rest of the request:

Tab What it holds
Params Query parameters.
Headers Request headers.
Body The request body.

Collections and folders

Requests live in collections, and a collection can hold folders. Each collection has its own variables, so values that belong to one set of endpoints do not leak into another.

Environments

An environment is a named set of variables. You keep one per target (local, staging, production) and switch between them with the environment selector in the request view. The variables in the active environment are what the request resolves against.

Authentication

Badami has built-in helpers for the common schemes:

  • Bearer token.
  • Basic username and password.
  • API key.

You can also link a credential from the vault, so a token is never typed into a request. The credential is read at send time and the secret stays in the vault.

Sending and reading the response

Requests run through the Rust backend, not the browser, so they are not subject to browser CORS rules. The response viewer shows the status, the headers, and the body, with a code view for the body when you want the raw form.

History

A history panel keeps the requests you have sent, so you can go back to one and resend or edit it instead of rebuilding it.

Import and export

Direction Format
Import Postman collections.
Export cURL.

Scoping to a project

Requests can be scoped to a project. A project has its own API panel, so the endpoints for one piece of work sit with the rest of that project instead of in a single global pile.
