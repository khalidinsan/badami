Bagaimana data mengalir

Frontend tidak pernah membuka berkas database secara langsung. Ia memanggil perintah Tauri, yang dilayani sisi Rust dari koneksi libsql yang terbuka:

  1. Sebuah aksi store memanggil invoke("db_query", …) atau invoke("db_execute", …).
  2. Kysely membangun SQL melalui dialect khusus yang driver-nya adalah pemanggilan invoke itu, sehingga kueri tetap type safe di frontend.
  3. Rust menjalankannya terhadap badami.db, atau terhadap replika sinkronisasi saat cloud sync aktif.

Layanan Local Dev adalah pengecualian: mereka proses nyata, bukan baris tabel. Supervisor memiliki siklus hidupnya, dan database hanya mencatat niat serta cuplikan status untuk UI. Kebenaran runtime berasal dari tabel proses dan pemeriksaan kesehatan.

Berkas database mana yang dibuka

Saat mulai, backend memilih strategi koneksi agar aplikasi bekerja offline:

Situasi Yang dibuka
Sinkronisasi aktif, replika ada Replika, seketika, tanpa menunggu jaringan.
Sinkronisasi aktif, replika belum ada badami.db selagi replika dibangun di latar belakang.
Sinkronisasi nonaktif badami.db sebagai berkas SQLite biasa.

Seluk-beluk Local Dev

Modul ini dipecah agar setiap berkas punya satu tugas:

Berkas Tanggung jawab
discovery.rs Melaporkan biner, datadir, port, dan entri resolver apa saja yang ada.
runtime_manifest.rs Membaca dan menulis manifes yang mencatat versi terpasang dan hash-nya.
runtime_updater.rs Mengunduh, memverifikasi, mengekstrak, dan memasang versi dari upstream.
datadir_migration.rs Menilai dan menjalankan clone APFS untuk datadir MariaDB.
config_gen.rs Menghasilkan konfigurasi nginx, FPM, dnsmasq, valet, dan MariaDB.
service_specs.rs Mengubah hasil penemuan menjadi definisi layanan yang dapat dijalankan beserta pemeriksaan kesehatan.
supervisor.rs Menjalankan, menghentikan, memulai ulang, dan memantau layanan; memiliki event stream.
sites.rs Parkir, tautkan, isolasi, amankan, dan buka situs.
tls.rs CA lokal dan sertifikat per situs.
bootstrap.rs Pemasangan LaunchDaemon dan resolver milik root.
doctor.rs Diagnostik hanya-baca dan perbaikan yang disarankannya.
mariadb_guard.rs Pemeriksaan pra-mulai yang mencegah server kedua membuka satu datadir.

Sinkronisasi dan data khusus mesin

Cloud sync mereplikasi database, tetapi beberapa baris hanya mendeskripsikan mesin ini: path biner, socket, dan pengaturan Local Dev. Tabel-tabel itu dikecualikan dari sinkronisasi agar mesin kedua tidak mewarisi path yang tidak ada di sana.
