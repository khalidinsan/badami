Local Dev

Stack PHP lokal yang lengkap di macOS: nginx, PHP-FPM dalam beberapa versi, MariaDB, Redis, dan dnsmasq, semuanya dari biner yang dipasang dan dikelola Badami. Tidak ada lagi yang perlu ada di mesin.

Hanya macOS

Local Dev bergantung pada path macOS, launchd, dan APFS. Modul ini disembunyikan di Windows dan Linux.

Cara penyusunannya

Semua yang dihasilkan Badami berada dalam satu folder, sehingga stack mudah diperiksa dan mudah dihapus: 

~/Library/Application Support/Badami/local-dev/
├── runtime/          binaries, one folder per role and version
│   ├── nginx/1.25.4/
│   ├── php/7.4/      php and php-fpm side by side
│   ├── mariadb/10.11.6/
│   ├── redis/7.4.7/
│   └── dnsmasq/2.89/
├── data/mariadb/     the database files
├── config/valet/     tld, parks, per-site certificates
├── config/php/74/    php.ini per version
├── nginx/            nginx.conf, sites/*.conf
├── fpm/              one pool per PHP version
├── socks/            unix sockets nginx connects to
├── pids/  logs/      runtime state
└── valet-server/     the PHP router that maps a host to a site folder

Memasang runtime

Buka Local Dev → Pengaturan → Runtime. Kartu ini mencantumkan setiap role dan versi yang terpasang untuknya, serta menandai mana yang sedang dipakai.

  1. Pilih Tambahkan versi. PHP 8.x berasal dari static-php-cli dan dnsmasq dari bottle Homebrew; keduanya diverifikasi terhadap checksum yang diterbitkan sebelum apa pun diekstrak.
  2. Pilih versi yang Anda inginkan. Versi itu diunduh, diverifikasi, diekstrak, lalu dijalankan pemeriksaan versi terhadap biner baru sebelum dipasang.
  3. Gunakan Gunakan pada sebuah baris untuk mengganti versi yang dijalankan sebuah role, dan ikon bin untuk menghapus versi yang tidak lagi dibutuhkan.
PHP 7.4 tidak punya build upstream

static-php-cli dimulai dari 8.0, dan tidak ada sumber netral lain yang menerbitkan build macOS arm64 di URL yang stabil. Karena itu Badami melaporkan 7.4 sebagai tidak tersedia untuk diunduh daripada menunjuk ke server orang lain. Jika Anda memerlukan 7.4, build sendiri dan letakkan di bawah runtime/php/7.4/.

Situs

Sebuah folder yang diparkir menyajikan setiap subfolder langsung sebagai situs, seperti cara kerja web root. Sebuah situs yang ditautkan menunjuk ke satu folder tertentu.

Aksi Hasil
Parkirkan direktori Setiap subfolder menjadi <folder>.test.
Tautkan proyek Folder proyek disajikan dengan namanya sendiri.
Isolasi PHP Mematok satu situs ke versi PHP tertentu melalui pool-nya sendiri.
Amankan Menerbitkan sertifikat dari CA lokal dan menyajikan situs melalui HTTPS.

HTTP dan HTTPS

Secara default nginx mengikat port tanpa hak istimewa, sehingga tidak ada yang berjalan sebagai root:

Mode URL Memerlukan admin
HTTP, default http://mysite.test:8080 No
HTTPS, per situs https://mysite.test:8443 No
HTTP di port 80 http://mysite.test Ya, sekali, untuk memasang LaunchDaemon

Port 80 bersifat opsional. Memasangnya menulis LaunchDaemon milik Badami di balik satu prompt admin, dan setiap konfigurasi yang dibaca daemon itu dirender ke folder milik root dan diverifikasi dengan hash sebelum daemon dimuat.

Mempercayai CA lokal

HTTPS langsung berfungsi, tetapi browser akan memperingatkan sampai Certificate Authority lokal dipercaya. Pengaturan → TLS menampilkan perintah persis yang akan dijalankan sebelum prompt admin muncul, dan sertifikatnya diverifikasi terhadap hash yang dihitung di aplikasi sebelum keychain melihatnya.

Menghapus kepercayaan itu dilakukan manual: gunakan Keychain Access, atau jalankan security remove-trusted-cert terhadap berkas CA.

DNS untuk *.test

Berkas resolver saja bukan DNS yang berfungsi: harus ada yang menjawab di port yang ditunjuknya. Badami memeriksa dengan me-resolve label acak, bukan dengan mencari berkas, dan melaporkan apa yang ditemukannya:

Mode Yang terjadi
Adopsi Listener yang sudah ada sudah menjawab untuk TLD tersebut, jadi tidak ada yang dijalankan.
Badami dnsmasq Memasang LaunchDaemon dnsmasq yang mengikat port 53. Satu prompt admin.
Port tinggi Menulis entri resolver yang menunjuk ke port tanpa hak istimewa, lalu menjalankan dnsmasq tanpa hak istimewa.
Terdegradasi DNS tidak berfungsi. Stack tetap berjalan dan situs menjawab di 127.0.0.1:8080 dengan header Host, dan tab Doctor menjelaskan cara memperbaikinya.
DNS aman di browser

Chrome dan Firefox dapat memakai DNS-over-HTTPS, yang sepenuhnya melewati berkas resolver. Nonaktifkan untuk *.test jika probe sistem berwarna hijau tetapi browser tidak bisa me-resolve situs Anda.

Database Anda

MariaDB membaca berkasnya dari data/mariadb. Jika Anda sudah punya datadir di tempat lain, Pengaturan → Runtime → Database files bisa memindahkannya ke sini. Di APFS pemindahan itu adalah clone, yang berbagi blok dengan sumbernya alih-alih menyalinnya: datadir 11 GB berpindah dalam sekitar satu detik dan hampir tidak memakai disk tambahan.

Pemindahan itu memverifikasi hasilnya dengan melakukan hash pada sampel berkas yang disalin, selalu termasuk ibdata1, dan membandingkan kedua sisi. Folder sumber tidak pernah diubah, jadi tetap tersedia sebagai cadangan sampai Anda menghapusnya sendiri.

Aturan keamanan

  • Tidak ada yang dihapus secara otomatis. Memindahkan data membuat clone; menghapus versi runtime atau datadir selalu merupakan tindakan eksplisit yang Anda lakukan.
  • Sebuah biner hanya dipakai jika hash-nya cocok dengan manifes yang dicatat saat dipasang. Berkas yang tersalin sebagian atau diubah terbaca sebagai tidak ada, bukan sebagai berfungsi.
  • Menjalankan MariaDB dua kali pada satu datadir ditolak. Dua server yang menulis berkas InnoDB yang sama adalah cara database menjadi rusak, jadi pengaman ini adalah kegagalan keras dengan penjelasan.
  • Konfigurasi berhak istimewa diverifikasi dengan hash. Konfigurasi nginx dan dnsmasq milik root dirender ulang, ditokenkan, diperiksa terhadap allowlist, distaging, dan diverifikasi hash-nya sebelum launchd memuatnya.

Menghapus instalasi

Local Dev → Pengaturan → LaunchDaemon membalikkan apa yang dipasang Badami: hanya menghapus unit milik Badami dan folder konfigurasi yang distaging. Berkas resolver hanya dihapus saat Anda mengonfirmasi dan hanya jika membawa penanda Badami, jadi berkas resolver yang ditulis oleh hal lain dibiarkan.

Untuk menghapus seluruh stack setelahnya, hapus folder yang ditunjukkan di bagian atas halaman ini dan folder milik root /Library/Application Support/Badami/local-dev-root/. Sertifikat yang Anda percayai harus dihapus dari keychain secara manual, seperti dijelaskan di atas.
